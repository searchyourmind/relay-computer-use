# Hosted synthetic demo

The Docker image runs the operator console and a private synthetic bank in one
service. Only the console is exposed. The bank binds to loopback port 4311.
This image supports deterministic replay, business outcomes, recovery, and
same-session human handoff. It contains no model and makes zero model calls.

Live discovery is deliberately unavailable in this small hosted environment.
The checked-in capability was generated by a real local Ollama discovery run;
the sanitized discovery evidence is in `evidence/discovery/`. Follow the root
README to reproduce discovery locally with `qwen3.5:2b`. There is no simulated
model provider or scripted substitute for discovery in this repository.

## Railway

Deploy this repository with its root `Dockerfile` and `railway.json`. Generate a
public HTTPS domain so Railway sets `RAILWAY_PUBLIC_DOMAIN`. Keep one replica:
live browser sessions and run ownership are process-local. `PORT` is supplied by
Railway. The image sets `RELAY_HOSTED=1` and `RELAY_ENABLE_DISCOVERY=0`.

The deployment targets the existing 1 GB memory limit. Omitting model weights
keeps the image and runtime small enough to evaluate replay without changing the
account plan. Validate actual resource use and replay after each deployment.
The console bounds concurrent work so only one Chromium run executes at a time.

The startup supervisor terminates both child processes if either service fails
and forwards shutdown to the console before stopping the bank. Railway waits up
to 120 seconds for `/api/health`. Do not create a public domain for port 4311.

Runtime runs are temporary and reset on redeployment. The checked-in sanitized
`evidence/capability.json` is always available for replay. No volume is needed for
this review demo. This is a synthetic evaluation surface, not a production
banking system.

## Local Docker check

```sh
docker build -t relay-demo .
docker run --rm --name relay-demo --memory=1g -p 4310:8080 \
  -e RELAY_HOSTED=0 relay-demo
```

Open `http://127.0.0.1:4310` and select replay. For full local model discovery,
use the root README instead of this restricted Docker image. Replay with
synthetic members `1001` and `1002`, then replay the `session` scenario through
Claim session → Restore session → Return control. Confirm different balances,
zero replay model calls, and the same session ID across handoff.
